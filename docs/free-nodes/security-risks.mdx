## 二、底层攻击机理一：恶意 TLS 降级、HTTPS 剥离与明文凭证窃取

很多用户有一个极其危险的认知误区：**“我平时访问的网站都是 HTTPS 加密的，挂了免费节点对方最多知道我访问了哪个域名，不可能看到我的密码吧？”**

在标准的 TLS 1.3 端到端严格校验下，这句话确实成立；**但黑产免费节点之所以能得手，正是通过以下三种底层技术手段击穿了你的 HTTPS 防线**。

### 2.1 `skip-cert-verify: true` 与传输层中间人劫持（MITM）

在代理协议中，客户端与代理服务器之间建立隧道时，通常依赖 TLS 证书验证对方身份；而当你的浏览器通过代理连接目标网站时，正常情况下浏览器会校验目标网站的证书。然而，许多野生免费订阅和魔改客户端采用了两种致命破坏方式：
1. **魔改客户端或诱导安装伪造根证书（Root CA）**：一些“永久免费加速器”会弹出提示要求安装所谓“安全加速组件证书”。一旦系统信任了黑产的根证书，蜜罐服务器就可以在出口处充当 **TLS Split-Proxy（SSL 拦截透明代理）**——它在后端用自己的客户端去连接真实的银行/Google，在前端用你本地信任的假证书即时签发一个一模一样的域名证书给你的浏览器。你的浏览器地址栏依然显示绿色小锁，但**所有加密文本已经在蜜罐服务器的内存里被明文解密、完整记录并重新加密转发！**
2. **隧道层 `skip-cert-verify: true` 泄密**：大量公开 Clash 订阅在节点参数中默认写入 `skip-cert-verify: true`。如果攻击者在入口与落地节点之间，或者在你的代理隧道协商阶段伪造证书实施中间人替换，客户端将毫无察觉地把你隧道内的完整请求明文拱手相让。

### 2.2 SSLStrip 恶意 TLS 降级攻击与非加密 HTTP 明文录包

即便你没有安装假证书，只要蜜罐节点控制了你的网络出口路由，它就能在应用层对你发起经典的 **SSLStrip（HTTPS 强制降级）** 攻击：
- 当你在浏览器地址栏直接输入不带协议头的 `example.com`（浏览器默认首先尝试请求 `http://example.com:80` 并期待服务端返回 `301 Moved Permanently` 跳转至 `https://`），或者点击了一个页面上的旧式 `http://` 链接时；
- 蜜罐服务器拦截了这个最初的 `HTTP 80` 端口请求，**自己代替你去向真实目标服务器建立 HTTPS 加密连接**；
- 随后，蜜罐服务器把目标网站返回的高安全 `HTTPS` 页面里的所有链接全部改写回 `http://`，去掉响应头中的 `Strict-Transport-Security (HSTS)`，并将 Cookie 中的 `Secure` 标记剥离，再传回你的浏览器！
- 如果你没有注意看地址栏已经退化成了“不安全”的 `HTTP`，在表单里输入了登录密码、论坛凭证或后台管理口令，**蜜罐服务器上的 `tcpdump` / `mitmproxy` 日志将在毫秒之间明文落盘保存你的账号密码**。

```
【SSLStrip 降级攻击数据包流转实录】
用户浏览器                     黑产蜜罐节点 (出口网关)               真实目标网站
    │                                  │                                 │
    │── 1. GET http://target.com ─────>│                                 │
    │   (未加密明文请求)                │── 2. GET https://target.com ───>│
    │                                  │<─ 3. 返回加密页面 & Set-Cookie ─│
    │                                  │                                 │
    │   [蜜罐在内存剥离 HSTS 与 Secure] │                                 │
    │<─ 4. 返回降级后的 HTTP 页面 ─────│                                 │
    │                                  │                                 │
    │── 5. POST 明文提交账号与密码 ────>│ (已记录用户密码与 Session!) ──>│
```

### 2.3 被严重低估的非加密协议与 API 明文凭证暴露

除了网页端，开发者和极客在终端或后台运行的大量工具比浏览器更容易在免费节点下“裸奔”：

## 三、底层攻击机理二：远程 DNS 投毒与虚假钱包/银行站钓鱼

在现代代理客户端（如 Clash/Mihomo 的 `Fake-IP` 模式或 `redir-host` 远程解析模式）中，当你访问境外甚至部分未正确分流的域名时，**究竟去哪个 IP 地址找服务器，是由远程代理出口节点代为执行 DNS 解析决定的**。这正是黑产蜜罐最喜欢使用的“降维打击”手段——**远程 DNS 投毒（Rogue DNS Poisoning）**。

### 3.1 为什么黑产不需要破解你的 HTTPS，也能让你乖乖把钱转走？

设想这样一个真实发生的钓鱼链条：
1. 你在某 Telegram 频道拿到了一个免费高速节点，导入客户端后开启了全局模式（或者订阅本身自带的恶意 `rules` 把某些金融域名划进了代理组）。
2. 你打开浏览器想访问常用的加密资产交易平台（例如 `binance.com` 或 `okx.com`）、某个开源软件下载站（例如 `github.com` 某个工具官网），或者某境外网银登录页。
3. 代理节点收到你的连接请求后，本地搭建的恶意 `CoreDNS` / `dnsmasq` 并没有返回官方真实 IP，而是返回了黑产预先租好的**高仿钓鱼服务器 IP**（或使用一个极度相似的同形异义域名，通过 HTTP `302` 重定向将你引导至视觉上 100% 一致的克隆前端）。
4. **致命之处在于**：钓鱼服务器拥有自己合法申请的 Let's Encrypt 证书！在面对相似域名跳转（例如把 `metamask.io` 重定向到 `metamask-security-update.com` 并弹出“检测到跨区异地登录，请重新导入 12 位助记词验证资产安全”的逼真弹窗）时，浏览器甚至不会报任何红字证书错误！
5. 焦虑中的用户一旦在伪造页面输入了助记词、二次验证码或网银交易密码，后台自动化脚本会在 **10 秒内** 将钱包资产全部转移归零。

### 3.2 针对开发者与软件下载站的“安装包投毒劫持”

类似的 DNS 投毒与入口替换还广泛针对开发者群体：
- 当你使用免费节点在 Google 搜索下载 `Clash Verge`、`Putty`、`Notepad++`、`Homebrew` 脚本或某个热门 `Python PyPI` / `GitHub` 第三方工具包时；
- 蜜罐节点将非 HSTS 强制保护或恶意跳转的下载镜像域名解析至黑产控制的静态分发服务器；
- 你下载下来的 `setup.exe` 或 `install.sh` 外观、版本号甚至数字体积都与官方无异，实则已被捆绑了远控木马（RAT）或浏览器凭证窃取器（InfoStealer，专门打包偷取你 Chrome 本地保存的所有网站密码与 Session Cookie）。

## 四、底层攻击机理三：HTTP 响应体篡改与恶意广告/挖矿脚本植入

如果你在连接免费节点期间浏览了一些尚未全面开启 HSTS 强制加密的传统论坛、技术博客、文档站或静态资源站，蜜罐出口服务器还会在转发 HTTP 响应流时，在 `</body>` 标签闭合前**动态注入一段经过高度混淆的 `<script>` 代码**。

这段注入的恶意 JavaScript 通常在后台悄无声息地执行三类破坏行为：
1. **浏览器后台算力挖矿（Cryptojacking）**：加载隐藏的 WebAssembly 挖矿模块，在你不知情的情况下将你的 CPU 占用率拉满到 80% 以上（表现为电脑风扇狂转、笔记本电池飞速掉电、网页卡顿），替蜜罐运营者挖掘门罗币（XMR）。
2. **全站点击劫持与返利劫持（Affiliate Hijacking）**：当你在电商或 SaaS 平台准备下单时，隐藏脚本在后台静默触发跳转并覆盖 Cookie 归因参数，将推广佣金或优惠券篡改为黑产账号。
3. **伪造“浏览器版本过旧/Flash 更新”弹窗木马**：向正常网页顶部强行渲染一条极具欺骗性的中文或英文系统提示条，诱导用户点击下载伪装成浏览器升级包的木马程序。

### 1. 我访问的网站全部都是 `https://` 开头，是不是用任何免费节点都绝对安全，不用担心密码被盗？

### 2. 为什么说在 Clash 配置里看到 `skip-cert-verify: true` 就必须拉响警报？
`skip-cert-verify: true` 的字面意思是“跳过 TLS 证书合法性校验”。正常情况下，如果有人试图拦截你的加密连接并伪造服务器证书，客户端会立即因证书验证失败而中断连接以保护你；一旦该选项被设为 `true`，客户端就变成了一个“瞎子”，无论是真服务器还是黑产架设的中间人监听服务器发来的假证书，它都会照单全收，加密通信的认证根基彻底坍塌。

### 3. 用免费节点时，如果我不小心开着全局模式打开了国内支付宝或网银，会被盗刷吗？
对于拥有独立硬件安全控件、HTTPS 双向证书固定（Certificate Pinning）与手机短信/人脸二次验证的现代手机银行 App 和支付宝而言，黑产节点很难仅靠一次代理转发就静默盗刷资金；**但极大的风险在于网页端会话劫持、周边非强校验的第三方系统、以及你泄露的个人敏感身份/消费/地址信息**。此外，国内银行或支付系统的安全风控引擎一旦检测到你的登录 IP 突然跳到了海外高危代理机房，极有可能直接触发账号保护性冻结，给你带来不必要的麻烦。

OpenAI 等大模型厂商的风控系统不仅监控你个人账号的对话内容，更极其看重**登录与调用 API 所在出口 IP 的历史信誉评分**。当你连接一个万人共用的免费节点时，在同一个出口 IP 上可能同时有几百个黑产脚本正在高频刷注册号、并发盗取额度或发送违规 Prompt。风控引擎会将该 IP 标记为极度恶意节点，并顺藤摸瓜对近期通过该 IP 活跃的关联账号执行连坐清退。
