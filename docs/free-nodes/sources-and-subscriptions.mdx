## 二、Base64 与 Subconverter 订阅转换底层原理解析

很多新手在面对一串看不懂的乱码文本（Base64 订阅），或者拿到一组 `vless://` 链接却不知道怎么导入 **Clash Verge Rev** 时，往往会感到困惑。搞懂订阅编码与转换的底层结构，不仅能帮你自主排查导入失败报错，更能避免重大隐私泄露。

### 2.1 V2Ray / Xray 通用 Base64 订阅到底是什么？

传统的 V2Ray（如 v2rayN、v2rayNG、Shadowrocket）通用订阅，本质上是一段经过 **标准 Base64 编码的纯文本多行字符串**。
当你在终端或解码工具中对订阅 URL 返回的文本执行 `base64 -d` 解码后，得到的是逐行排列的节点 URI，常见协议前缀格式如下：

```text
# 解码后的标准节点 URI 结构示意（以下为脱敏格式示例）
ss://YWVzLTI1Ni1nY206cGFzc3dvcmQ=@198.51.100.10:8388#HK-Free-01
vmess://eyJ2IjoiMiIsInBzIjoiVVMtVGVzdCIsImFkZCI6IjE5OC41MS4xMDAuMTEiLCJwb3J0IjoiNDQzIiwiaWQiOiIwMDAwMDAwMC0wMDAwLTAwMDAtMDAwMC0wMDAwMDAwMDAwMDAiLCJuZXQiOiJ3cyIsInRscyI6InRscyJ9
vless://00000000-0000-0000-0000-000000000000@198.51.100.12:443?encryption=none&security=tls&type=ws&path=%2Fws#SG-Edge
trojan://secretpassword@198.51.100.13:443?sni=example.com#JP-Backup
hysteria2://authpassword@198.51.100.14:443/?sni=example.com#US-QUIC
```

**常见导入报错原因速查**：
- **Base64 补位缺失（Padding Error）**：部分简陋脚本拼接字符串时丢掉了末尾的 `=` 或 `==`，导致部分严格校验的客户端解析崩溃。
- **混入中文或非法 Emoji 节点备注**：未经过 URL Encode 的特殊字符可能导致老旧解析器截断。
- **协议代际不兼容**：2026 年广泛使用的 `VLESS-Vision`、`Reality`（`security=reality`）以及 `Hysteria2` 协议，**无法被早已停更的老旧原版 Clash 内核识别**，必须使用基于 **Mihomo（原 Clash Meta）内核** 的客户端（如 Clash Verge Rev、FlClash、Shadowrocket）才能正确解析！

### 2.2 Subconverter 订阅转换的工作原理与“公共后端泄密红线”

**Subconverter** 是开源社区最核心的订阅格式转换引擎。它的工作流程非常简单：
1. 接收上游订阅地址（`url=` 参数）以及目标客户端类型（`target=clash`、`target=surge` 等）和外部规则配置模版（`config=` 参数）。
2. 在 Subconverter 后端服务器拉取原始 Base64 文本或节点链接，将其逐条反序列化为统一的内部节点对象。
3. 按照目标模版的 `proxy-groups`（策略组，如自动选择、故障转移、AI 分流）与 `rules`（路由规则）重新渲染，输出一份完整的 Clash YAML 配置文件返回给客户端。

> ⚠️ **极度危险的操作警告：严禁向陌生公共在线转换网站提交私人或付费订阅！**  
> 互联网上有大量免费的第三方在线“订阅转换工具网页”。你在网页输入框里填入订阅链接并点击“生成 Clash 链接”时，**你的原始订阅 URL（包含你付费机场的身份鉴权 Token）会以明文 HTTP GET 参数的形式发送给该转换网站的后台服务器**。

## 三、免费订阅源安全审计与死链清洗四步实操

当你拿到一条公开的 Clash YAML 订阅或 Base64 文本后，**绝对不要直接用客户端 URL 导入后马上开启系统代理**！正确做法是先将其下载为本地文本文件，执行一轮 3 分钟的「静态安全审计与死链预清洗」。

### 3.1 第一步：静态安全审计（排查恶意参数与路由劫持）

用 VS Code、Notepad++ 或终端工具打开下载下来的 YAML 文件，重点检查以下三处高危区域：

1. **检查 `proxies:` 节点段里的 TLS 与证书参数**：
   全局搜索 `skip-cert-verify`。如果发现大批节点写着 `skip-cert-verify: true`，这是极具风险的信号——客户端将完全放弃验证远程服务器 TLS 证书真伪，极易遭受中间人窃听。**清洗时必须全部替换为 `false` 或删除，若因此连不上就直接删掉该节点**。
2. **检查 `proxies:` 中的异常主机地址（`server` 字段）**：
   剔除明显伪造的环回地址、内网地址或广告占位节点（例如 `server: 127.0.0.1`、`0.0.0.0`、`192.168.x.x` 或域名本身就是赌场/色情引流网址的假节点）。
3. **重点审计 `rules:` 路由规则段与 `dns:` 段（防止规则投毒）**：
   很多恶意分享者在公开 YAML 文件的 `rules` 最前面偷偷夹带几行私货，比如：
   - 将网银、交易所或购物返利域名强行指向 `PROXY`（诱导你的金融流量绕道他的蜜罐节点）；
   - 将 `dns.nameserver` 指向来源不明的境外小众 IP，借此实施远端 DNS 投毒。
   **最彻底的防御手段**：直接删掉免费 YAML 文件自带的整个 `dns:` 和 `rules:` 段，**仅保留经过清洗的 `proxies:` 节点列表，然后套用本文第五节提供的洁净安全隔离模板**！

### 3.2 第二步：清理无效协议与重复冗余节点

对于通过脚本抓取汇总的数百条免费节点，往往混杂着大量格式损坏或重复 IP/端口组合。你可以使用简单的脚本或文本工具在导入前完成去重与协议过滤：

```bash
# 示例：使用 Linux/macOS/Git Bash 快速解码 Base64 订阅并过滤无效占位行
curl -sSL "你的公开免费文本订阅URL" | base64 -d 2>/dev/null \
  | grep -E "^(vless|vmess|trojan|ss|hysteria2)://" \
  | grep -vE "127\.0\.0\.1|0\.0\.0\.0|localhost" \
  | sort -u > cleaned_nodes.txt

# 统计清洗后剩余的候选节点数量
wc -l cleaned_nodes.txt
```

### 3.3 第三步：利用脚本或客户端快速剥离 100% 死亡节点

在把几十个候选节点丢进日常使用的配置前，先在一个独立的临时配置文件（Profile）中执行初筛：
1. 在 **Clash Verge Rev** 中点击「新建（New）」创建一个临时本地 Profile，仅粘贴清洗后的 `proxies:` 与最基础的 `ALL` 手动选择策略组。
2. **此时先不要开启「系统代理（System Proxy）」也不要开启「TUN 模式」**！客户端自身在未接管系统流量的情况下，依然可以对列表内的节点发起内置的延迟测试。
3. 点击节点列表顶部的「延迟测试（闪电图标）」，耐心等待所有并发测试完毕。
4. 剔除所有显示 `Timeout`、`Error` 或 `0ms` 的完全失联死链节点。

## 四、Clash Verge Rev 批量节点真实连通性与延迟压测教程

很多用户疑惑：“为什么我在 Clash Verge Rev 里点击测速，明明有 15 个节点显示绿色 `120ms`，可切过去打开 Google 却一直白屏？”这是因为 **URL-Test 返回状态码，并不等于带宽可用、也不等于没有假节点劫持**。

在 2026 年的 **[Windows](/docs/clients/windows)** 与 **[macOS](/docs/clients/macos)** 平台下，使用基于 Mihomo 内核的 **Clash Verge Rev** 对免费节点进行真实可用性压测，应当遵循以下三阶验证标准：

### 4.1 修改测速验证目标（摆脱 `generate_204` 假延迟误导）

默认情况下，Clash 使用 `http://www.gstatic.com/generate_204` 作为延迟测试接口。部分黑产蜜罐或中间网关会针对该明文 HTTP URL 直接本地伪造返回 `204` 状态，从而在面板上刷出 `25ms` 的假数字。

**进阶操作**：进入 Clash Verge Rev →「设置（Settings）」→「Clash 设置 / 延迟测试 URL（Latency Test URL）」，将测速地址改为经过真实完整 TLS 握手且不易被轻率缓存的 HTTPS 端点，例如：
- `https://cp.cloudflare.com/generate_204`（验证完整 TLS 1.3 握手与 Cloudflare 边缘回源连通性）
- 或 `https://www.google.com/generate_204`（需确认支持真实 TLS 解析，剔除无法完成端到端 HTTPS 握手的坏节点）

### 4.2 区分“握手延迟”与“真实有效吞吐”

通过 `HTTPS` URL-Test 筛选出绿色延迟的节点后，可能只剩 3~8 个真正完成 TLS 握手的幸存节点。接下来必须验证其**实际传输带宽与丢包率**，因为很多免费节点虽然能握手成功，但下行速度仅有 `20 KB/s`（丢包率 40% 以上），根本无法加载现代网页。

你可以在仅启用「局部浏览器代理」（例如在无痕浏览器配置 `127.0.0.1:7897` SOCKS5/HTTP 局部代理，不开启全局系统代理）的前提下，执行终端测速验证：

```bash
# 通过 Clash Verge Rev 默认混合代理端口 (7897) 测试当前选中节点的真实出站 IP 与响应耗时
curl -x http://127.0.0.1:7897 -o /dev/null -s -w \
  "DNS解析: %{time_namelookup}s\nTCP连接: %{time_connect}s\nTLS握手: %{time_appconnect}s\n首字节(TTFB): %{time_starttransfer}s\n总耗时: %{time_total}s\n平均下载速度: %{speed_download} B/s\n" \
  https://speed.cloudflare.com/__down?bytes=5000000
```

**合格阈值参考**（见 [测速方法论说明](/docs/observatory/speedtest-guide)）：
- 若 `TLS握手` 超过 `2.5s`，说明跨境公网丢包极为严重，网页打开会极度痛苦；
- 若 5MB 小文件测试的 `平均下载速度` 低于 `500000 B/s`（约 4 Mbps），基本无法流畅观看 1080P 视频，仅能勉强查阅纯文本；
- 若出现 `SSL certificate problem` 报错，说明该免费节点存在证书异常或中间人劫持企图，**必须立即永久拉黑删除**！

### 4.3 检查真实出口 IP 与所在 ASN（排除蜜罐与高危代理池）

使用完连通性测试后，在隔离的测试浏览器访问 `https://ipinfo.io/json` 或在终端运行：

```bash
# 查看当前免费节点真实的落地公网 IP、国家/地区与 ASN 归属组织
curl -x http://127.0.0.1:7897 -s https://ipinfo.io/json
```

如果发现出口 IP 属于声名狼藉的乱七八糟小众挂机房，或者归属地与节点名称标注（如“香港专线”）完全不符（实际落地在乌克兰、俄罗斯、巴西或某不明住宅肉鸡段），则该节点极可能属于交叉转卖的污染池或蜜罐，**绝对不可在该节点上登录任何账号**！

function main(config) {
  if (Array.isArray(config.proxies)) {
    config.proxies = config.proxies
      // 过滤掉指向本地环回或明显非法的假节点地址
      .filter((p) => p.server && !/^(127\.|0\.0\.0\.0|localhost)/i.test(p.server))

## 七、订阅获取、转换与安全验证 10 大实战 FAQ

### 1. 为什么我把 Base64 免费订阅链接直接粘贴进 Clash Verge Rev 会提示解析失败？
部分老旧的免费订阅链接返回的是纯粹的 Base64 编码的 `vmess://` / `vless://` 节点行，而非标准的 Clash YAML 格式（包含 `proxies:` 和 `rules:` 字段）。虽然新版 Clash Verge Rev 对常见 URI 具备一定兼容解析能力，但遇到格式不规范或缺失补位的订阅仍可能报错。此时建议在本地通过 Docker 启动离线的 `Subconverter` 容器将 Base64 转换为标准 YAML 后再导入。

### 2. 我能不能直接用百度/谷歌搜出来的在线“免费订阅转换网页”把 V2Ray 转成 Clash？
**强烈不建议！尤其绝对不要用来转换任何付费机场的订阅链接！** 在线转换服务需要把你的原始订阅 URL 发送到对方的后端服务器进行抓取渲染。若该网站由黑产架设，后台只需一行日志脚本就能窃取你的付费订阅 Token 并盗刷你的全部流量；即使是转换免费节点，恶意转换后端也可能在你不知情的情况下向生成的 YAML `rules` 段里注入劫持银行或返利网站的恶意分流规则。

### 3. 为什么有的免费订阅在导入后，Clash Verge Rev 提示 `Unsupported proxy type` 或无法启动内核？
这通常是因为订阅中混入了格式错误的字符串、已淘汰的奇葩加密方式（如部分已移除的 Shadowsocks 旧加密算法），或者你的客户端内核版本过旧，无法解析 2026 年主流的 `VLESS-Reality` 或 `Hysteria2` 参数字段。请确保在 Clash Verge Rev 的设置中将内核切换并更新至最新的 **Mihomo（Clash Meta）稳定版**，不要使用早已停止维护的旧版原版 Clash 内核。

### 4. 客户端测速显示的延迟（比如 `65ms`）为什么和实际打开网页的速度完全不匹配？
`URL-Test` 测试的是客户端发送一个极小的 `generate_204` HTTP 探测包并收到空响应的往返耗时，**它既不测试持续下行吞吐带宽，也不代表当前线路没有丢包**。许多免费节点由于瞬时并发极高，小数据包能挤过去（显示 65ms），一旦加载包含几十个 JS/CSS 与图片资源的网页，大包就会在拥塞队列中大面积丢弃并卡死。务必配合 `curl` 小文件测速验证实际吞吐。

### 5. 如果免费订阅里几乎所有节点都设置了 `skip-cert-verify: true`，我改成 `false` 后全红超时了怎么办？
**立刻全部删除，绝不姑息！** 如果一个节点在开启正常 TLS 证书校验后就无法连通，说明它的 TLS 证书要么已过期、要么证书域名与节点配置不匹配、要么它正处于某种拦截或中间人篡改状态。为了图省事而保持 `skip-cert-verify: true`，等于把你访问海外站点时的身份验证防护罩亲手摘掉，风险远大于收益。

### 6. 在配置文件里写了 `GEOSITE,cn,DIRECT` 和 `GEOIP,CN,DIRECT`，为什么国内网银的域名还会被免费节点解析 DNS？
因为传统的 `GEOIP,CN,DIRECT` 规则在匹配之前，客户端可能需要先做一次域名解析才能拿到目标 IP 去比对 GeoIP 库。如果你的 `dns` 配置没有正确配置 `fake-ip-filter` 与国内 `nameserver` 分流，部分国内域名就可能先被送去远程 DNS 或 Fake-IP 池处理。因此，**务必像本文第五节模板那样，把所有银行、支付、政务域名同时显式写入 `fake-ip-filter` 白名单与前置 `DOMAIN-SUFFIX` 直连规则中**。

### 7. 移动端使用 Shadowrocket（小火箭）或 v2rayNG 导入免费节点时，怎么做到同等级别的安全隔离？
在 **iOS Shadowrocket** 中，切勿使用「全局路由：代理」，请将全局路由固定在「配置（Config）」，并使用自带严格直连分流的本地 `.conf` 配置文件，同时在节点编辑页确认关闭「允许不安全（Allow Insecure）」开关。在 **Android v2rayNG** 中，务必开启「分应用代理（Per-app Proxy）」，只勾选你需要临时使用的某一个浏览器，彻底放行微信、支付宝、银行 App 与通讯软件，并在路由设置中启用「绕过局域网及中国大陆地址」。

### 8. 开源仓库里的 `clash.yaml` 文件动辄上万行，我怎么快速检查里面有没有藏着恶意规则？
不要用肉眼逐行翻看上万行文本。你可以先用文本编辑器折叠或直接删除原文件的 `dns:`、`rules:` 和 `rule-providers:` 段落，**只提取出它的 `proxies:` 节点列表部分**，然后合并到你自己在本地维护、绝对可控的极简隔离模板（例如本文第五节提供的安全配置）中使用。

### 9. 我按教程清洗完了，发现 100 个免费节点里最后真正能打开网页的只有 2 个，这是正常的吗？
**完全正常，甚至可以说是 2026 年公开免费节点池的真实写照。** 实验室连续抽样拨测表明，公开聚合池里超过 80% 的节点要么已被防火墙阻断端口、要么已欠费停机、要么处于超负荷拥塞假死状态，最终从国内三网实际能稳定跑通完整 TLS 握手的往往不足 5%~10%。这也是为什么我们反复建议不要把生产时间浪费在反复洗池上。
