## 一、机场后端架构如何监控连接：IP 并发数 vs TCP 连接数限制

很多用户看到套餐介绍写着“支持 3 台设备在线”或“限制同时连接数”，经常产生疑惑：机场服务端远在千里之外，它既看不到我的电脑主板序列号，也读不到手机 MAC 地址，究竟是怎么统计我用了几台设备的？

### 1. 服务端两套核心并发计数模型对比

在主流机场后端管理面板（如 V2Board、Xboard、SSPanel-Uim 搭配 XrayR / V2bX 节点后端）中，限制机制分为两个完全不同的维度：

```
用户端请求 ──> [本地路由器/宽带/5G基站] ──> (分配公网出口 IP + 发起多条 TCP/UDP Socket)
                                                   │
                                                   ▼
                                       [机场节点后端 (XrayR / V2bX)]
                                       ├── 维度 A：IP 并发统计 (按 60~180 秒滑动窗口去重统计接入的源公网 IP 数)
                                       └── 维度 B：TCP 连接数统计 (统计单用户同一毫秒保持的 Active Socket 总数)
```

| 限制维度 | 技术统计原理 | 日常典型场景影响 | 超限后的系统惩罚表现 |
| :--- | :--- | :--- | :--- |
| **IP 并发数限制**（如限 3~5 个 IP） | 后端节点每隔几十秒向中心面板上报一次“当前活跃用户的源公网 IP 列表”，面板汇总去重。若设定上限为 3 个 IP，则最多允许 3 个不同公网 IP 同时传输流量。 | **家庭同一 Wi-Fi 下**：电脑、手机、平板、电视全连家里路由器，外界看来只有 **1 个家庭宽带公网 IP**，全部畅通；<br/>**跨网络同时使用**：家里挂着软路由（IP 1）+ 手机开 5G 出门（IP 2）+ 公司办公（IP 3）+ 借给外地同学（IP 4），此时触发超限！ | 新发起的连接会被节点直接拒绝（日志报 `EOF` 或 `connection reset`），严重频繁超限将触发系统自动封号或临时锁定 15 分钟。 |
| **TCP 连接数限制**（如限 100~300 连接） | 限制单个用户 UUID 在单台或全网节点上同时维持的并发 TCP/UDP 会话句柄数量，防止个人爬虫或多线程下载软件耗尽服务器端口表与内存。 | **普通上网与 4K 视频**：通常仅占用 **5~25 个** 并发连接；<br/>**高并发风险行为**：开启浏览器自动恢复 80 个标签页、使用 IDM/Aria2 32 线程狂下大文件、挂着高频 API 量化抓取脚本，瞬间突破 200+ 连接。 | 多余的新建连接直接被丢弃超时，网页图片加载不全，或节点瞬间无响应卡死几秒后恢复。 |
| **速率限制 (Speed Limit)** | 部分极低价入门套餐在后端配置单用户峰值限速（如限 100Mbps 或 200Mbps）。 | 测速最高只能跑到套餐标称峰值，通常不影响看 4K 视频，但多线程大文件下载达不到千兆满速。 | 达到阈值后带宽曲线呈一条水平直线，不会因此封号。 |

### 2. 实用设备规划建议
- **个人多端协同**：在主流专线机场（例如 [光速云](/docs/brands/guangsu) 标准套餐支持 **3 至 5 台设备同时在线**）下，只要不把订阅发给异地朋友，个人在家里挂软路由、出门用手机 5G、去公司开笔记本，完全游刃有余；
- **关闭不必要的“自动测速与并发轮询”**：在客户端中，不要把自动测速间隔设得太短（例如每 30 秒批量 ping 60 个节点），这会在瞬间创建上百条并发短连接，不仅浪费电量，也极易干扰正常并发统计。

## 二、后端“审计规则”全面揭秘：BT/PT 屏蔽与 SMTP 25 端口封禁

使用机场过程中，很多人遇到过“挂着代理下种子速度永远是 0”、“邮箱软件发不出邮件”甚至“刚下载一个文件账号突然被警告封停”的情况。这些并非节点坏了，而是触碰了机场生存的底线——**后端安全审计规则（Audit Rules）**。

### 1. 为什么所有正规机场都死死封杀 BT / PT 下载？
- **天价版权罚单与上游拔线风险（DMCA）**：中国香港、日本、新加坡、美国及欧洲正规数据中心机房对版权侵权（DMCA Takedown）实行零容忍政策。一旦你在连着机场节点的状态下打开 qBittorrent、uTorrent、BitComet 或国内某些内置 P2P 吸血引擎的下载器去拖影视或游戏种子，版权监测机构在几分钟内就能抓到落地机 IP 的做种握手记录，并直接向 IDC 机房发送侵权投诉。机房收到 1~2 次投诉就会毫不留情地**直接停机清退整台服务器**，甚至冻结押金。
- **技术拦截特征**：节点后端通常通过正则匹配与特征识别（L7 DPI）实时阻断以下内容：
  - BitTorrent 握手协议特征字（`BitTorrent protocol`）；
  - 常见 PT 站与公开 Tracker 域名（`announce`、`tracker`、`torrent` 关键词）；
  - 迅雷 P2P 特征及常见电驴、磁力链接下载端口。
- **合规替代做法**：下载任何种子、网盘或大型单机游戏时，务必切回 **Rule 规则模式** 并确保下载工具本身在分流规则中设为 **`DIRECT` 直连**，或临时关闭代理客户端的 TUN 模式后再进行 P2P 下载。

### 2. 为什么 SMTP 25 端口被全网封禁？对日常收发邮件有什么影响？
- **反垃圾邮件国际联防机制**：TCP **25 端口**是互联网最古老的明文邮件发送中继端口。黑客和垃圾邮件制造者最喜欢购买廉价代理账号批量连接境外邮件服务器的 25 端口狂发钓鱼邮件和广告（SPAM）。一旦某台落地服务器的 IP 因为发垃圾邮件被列入 **Spamhaus** 等全球反垃圾邮件黑名单，这台服务器上所有正常用户的邮件服务、甚至正常的网页访问信用分都会瞬间崩塌。因此，不仅机场后端审计默认封禁 25 端口，连 AWS、GCP、Azure 等上游云厂商也都在母机防火墙默认封死了出站 25 端口。
- **如何解决邮箱客户端发送失败？**
  1. **国内邮箱（QQ 邮箱、163 邮箱、企业微信/阿里企业邮箱）**：在分流规则中将其域名与服务器地址设为 `DIRECT` 直连，不经过机场节点；
  2. **海外邮箱（Gmail、Outlook、ProtonMail、企业自建海外邮局）**：在 Outlook / Thunderbird / Apple Mail 客户端的账户设置中，将发信服务器（SMTP）端口从老旧的 `25` 修改为现代加密端口 **`465`（SSL/TLS）** 或 **`587`（STARTTLS）**，收信端口使用 **`993`（IMAP SSL）**。机场审计放行 465 与 587 加密发信端口，修改后即可丝滑收发邮件。

### 3. 机场常见禁止访问的其他高危审计红线
除 BT/PT 与 25 端口外，合规机场的审计黑名单通常还包括：
- **端口扫描与暴力破解工具流量**（如在开着代理的情况下跑 `nmap` 扫描境外 IP 段、SQL 注入测试或 SSH 爆破脚本）；
- **数字货币挖矿矿池协议**（Stratum 协议特征）；
- **高危违法违规站点、恐怖主义或恶意网络攻击目标**；
- **部分敏感政治垃圾宣传或涉诈高危域名**（防止机场中转入口遭重点溯源关停）。

## 三、账号合租封号机制与防泄露安全准则

在社交平台上经常能看到“某某顶级专线机场 4 人拼车合租，每人每月只要几块钱”的帖子，但实际踩坑封号的案例每天都在上演。

### 1. 为什么“拼车合租”是封号率最高的危险行为？
1. **异地多 IP 并发瞬时越线**：4 个人分别在不同城市，每人手里又有手机 5G 和家里 Wi-Fi 两套网络，合起来动辄产生 6~8 个活跃公网 IP，远远突破标准套餐 3~5 个 IP 的并发上限；
2. **审计违规“一人犯错、全车连坐”**：即使你老老实实只查资料，只要合租的另外某一个人半夜忘关迅雷下载了个电影，或者拿代理挂了个爬虫，系统直接判定该订阅账号恶意滥用，整账号永久封停且申诉无门；
3. **订阅链接二次转卖风险**：任何拿到订阅 URL 的人都拥有完整节点使用权。一旦某位拼车者把订阅链接泄露到免费节点分享群或第三方在线转换工具，几个小时内几百 GB 流量就会被陌生人刷光；
4. **账务与所有权纠纷**：账号注册邮箱与密码掌握在“车主”一人手中，一旦车主中途换密码或跑路，合租者没有任何申诉凭据。

拼车省下几块钱却承担随时断网封号与隐私暴露的风险完全得不偿失。以本站首推的 **[光速云](/docs/brands/guangsu)** 为例，其**轻量版年付仅 ¥99/年（折合每月 ¥8.25，每月 69GB IEPL 物理专线流量）**，使用优惠码 **`AMM`** 后成本更低。用一杯奶茶三分之一的价格独享一条高可靠企业级物理专线，远比担惊受怕去和陌生人拼车划算得多。
:::

### 2. 日常账号与订阅链接的 4 项安全防线
1. **订阅链接绝对保密**：绝不要把带有 `token=` 的完整订阅地址截图发在微信群、论坛求助帖或 Github 公开仓库中；需要排查规则配置问题时，务必先删除敏感 Token 字段；
2. **警惕不明来源的“在线订阅转换后端”**：市面上有许多个人搭建的免费 Subconverter 网页转换工具，恶意搭建者可以直接在服务器后台记录你粘贴进去的订阅 URL 从而盗用你的流量！如今 **Clash Verge Rev** 与 **FlClash** 等现代客户端早已原生支持直接导入通用订阅及本地模板覆写，尽量直接使用机场官方原生订阅链接，无需经过第三方未知转换站；
3. **独立高强度密码 + 开启两步验证（2FA）**：不要在不同小机场使用相同的常用邮箱密码组合，防止某个小平台脱库撞库；若官网支持 Google Authenticator 等 TOTP 二步验证建议开启；
4. **怀疑泄露立刻“重置订阅链接”**：一旦发现官网后台“已用流量”在自己没用电脑时暴涨，立即登录用户中心点击 **「重置订阅信息 / 重置 UUID」** 并修改登录密码，可在 1 秒内令旧链接全部失效止损。

## 五、海外合规支付通道安全与科学退款流程

### 1. 为什么机场支付常跳转到第三方收银台？如何识别安全支付环境？
由于跨境网络加速服务涉及跨境结算与行业监管差异，正规机场通常不会用境内个人实名微信号直接收款，而是接入**合规海外商户聚合支付网关（如 Stripe、AlipayHK 跨境通道、第三方海外持牌支付接口）或 USDT（TRC20/ERC20）数字货币结算**。

支付安全核验三原则：
- **只认官网后台直接跳转**：永远只从自己登录后的机场官方仪表盘内部点击支付跳转，绝不通过陌生私人微信、Telegram 私聊代充或来路不明的发卡网转账；
- **核对金额与币种汇率**：部分海外通道会按实时汇率折算为港币或美元显示，付款前核对最终扣款金额是否在合理汇率波动范围内；
- **小额试错防跑路铁律**：面对任何新接触的机场品牌，无论广告吹得多天花乱坠，**第一次永远只买最低档月付套餐**，实测验证晚高峰 20:00-23:00 的真实连通率与客服工单响应速度后，再决定是否升级年付或永久套餐。

### 2. 买错套餐或线路不匹配：正规合规退款流程指南
虽然虚拟数字订阅商品一经激活存在节点暴露与流量消耗成本，但多数信誉良好的老牌服务商针对以下合理情形仍提供人性化处理方案：
- **常见可协商场景**：购买后 **24 小时内且已用流量极低（例如低于 1GB 或 5%）**，因本地特殊校园网/企业专网彻底无法连接；或者不小心重复支付了同一笔订单、买错了套餐周期想升级补差价。
- **标准合规维权步骤**：
  1. **暂停流量消耗**：一旦发现无法正常使用或买错方案，立刻停止使用该节点，不要把流量刷掉一半再申请；
  2. **官网提交详细工单**：登录官网用户中心「我的工单」，清晰写明**订单编号、问题发生时间、客户端报错日志截图或命令行 `Test-NetConnection` 结果**，礼貌提出“退回账户余额更换其他套餐”或“按平台 ToS 申请原路退款”；
  3. **禁止先恶意投诉再沟通**：部分用户在遇到不会配置的本地故障时，不发工单直接到支付宝/支付通道发起欺诈投诉。这不仅会导致你的账号被全行业黑名单系统联动拉黑，还会污染支付接口连累其他正常用户的续费通道。绝大多数合规运维在核实未消耗流量且确属网络不兼容后，都会妥善处理。

## 六、账号安全与计费风控高频 FAQ（10 问 10 答）

### Q1：同一台电脑上同时开启 Chrome、Terminal 和手机热点共享给平板，这算几台设备在线？
**A**：算作 **1 个公网出口 IP**（只要你的电脑是主力出口设备，或者手机和平板连在同一个路由器下）。后端不看你的终端数量或同时开了几个软件，只看**抵达节点服务器的源头公网 IP 地址个数**。当然，如果你给手机开了 5G 流量热点并独立让电脑也连一个不同的运营商宽带，才会产生 2 个不同的出口 IP。

### Q2：如果我把家里的 OpenWrt 软路由连上机场，全家 15 台智能设备（手机、电视、电脑、iPad）同时用，会不会触发 3~5 台设备封号限制？
**A**：**完全不会！** 在软路由（OpenClash / PassWall）模式下，家里所有连在路由器 Wi-Fi 下的设备流量全部先汇聚到软路由上，再统一由软路由的宽带公网 IP 封装加密发往机场节点。在机场后台看来，永远只有 **1 个 IP 地址（你家软路由的 IP）** 在稳定连接，极其安全。

### Q3：为什么我出差住酒店、经常切换公司/家里/高铁 5G 网络，IP 一直在变，会不会被误判成合租封号？
**A**：放心，正规面板的 IP 并发计数采用的是**“短时间滑动窗口（通常 1~3 分钟）”**。当你离开家里断开 Wi-Fi 坐高铁切到 5G、再连到酒店 Wi-Fi 时，前一个网络旧 IP 的连接已经断开超过窗口期，系统只计入当前活跃的新 IP。只有**同一分钟内**在广州、上海、北京三个不同地方同时产生高并发流量，才会被风控引擎判定为多地多人合租。

### Q4：听说有的机场不限设备数量，是不是比限制 3~5 台设备的机场更好？
**A**：不一定，甚至可能存在隐性陷阱！对于同一价格档位的套餐，如果一家机场号称“不限设备”，往往意味着大量用户会拿去几人甚至十几人疯狂拼车合租，导致同一台节点服务器上挤满了几倍于正常水平的真实人口，**晚高峰带宽被严重挤兑、IP 纯净度极速恶化（AI 秒封）**。合理的 3~5 台并发限制（配合软路由不限下级终端）恰恰是保护全体付费用户高速体验与落地 IP 纯净度的健康护城河。

### Q5：购买了光速云“147 永久套餐（247GB 不过期）”，如果我只做轻度网页浏览，能用多少年？
**A**：以纯文字查资料、收发 GitHub 代码、日常用 ChatGPT 对话和查阅海外技术文档为例（不看 4K 视频），普通人每个月消耗流量通常仅在 **3GB ~ 8GB** 之间。按每月 5GB 计算，247GB 流量足够持续稳定使用 **4 年以上**，且期间无需操心任何月度续费与到期清零问题，非常适合作为长期科研、办公或应急备用的“终身防失联底牌”。

### Q6：使用机场节点时，需要担心自己的微信聊天记录、网银密码或 Git 代码被机场老板看到吗？
**A**：**不需要过度恐慌，但要懂得基本边界**。现代互联网绝大多数服务（包括网银、微信、GitHub HTTPS、ChatGPT）本身在你的电脑与目标网站之间就建立了 **端到端 HTTPS / TLS 加密隧道**。机场节点只能看到你“正在访问 `github.com` 或某个 IP 地址（SNI/DNS 层面）”，**绝对无法解密 HTTPS 内部传输的账号密码、聊天正文或代码内容**——前提是你没有主动在电脑上安装来路不明的第三方自签名 MitM 根证书。至于明文 HTTP（无锁图标）的古老网站，任何网络中间商都能看到，日常应避免在无加密页面输入敏感信息。

### Q7：我在官网充值了钱包余额，但还没买套餐，为什么节点还是连不上？
**A**：这是新手常见操作误区！绝大多数机场将“账户钱包余额”和“有效订阅套餐”分开计算。充值成功仅仅代表你的账户里有了代金币，你**必须再进入「购买订阅」页面，选择心仪套餐并使用“余额支付”完成套餐购买下单**，系统才会为你生成有效的节点订阅链接和分配流量配额。

### Q8：套餐里的流量还没到重置日就提前用完了，必须等下个月还是可以提前重置？
**A**：主流机场用户中心通常都在套餐管理卡片下提供一个 **「流量重置包 / 重置当前流量」** 按钮（需支付少量重置费即可立刻恢复当月满额流量，但不会改变原有到期日）；或者也可以直接在后台升配到更高一档流量的套餐。具体操作可在官网仪表盘的“我的订阅”中查看。

### Q9：忘记了机场官网最新域名打不开了（被屏蔽了），我还能通过什么方式找回账号和更新订阅？
**A**：为了防范官网主域名遭遇阻断失联，请养成买完机场后顺手做两件事的习惯：第一，保存官方发在仪表盘公告里的**“防失联永久发布页域名”或官方 Telegram 频道/客服邮箱**；第二，即使官网首页打不开，你客户端里原有的订阅 API 地址往往使用的是独立的托管域名，先开启任意可用节点再点击客户端「更新订阅」通常就能拉取到公告栏提示的最新官网地址。

### Q10：机场账号快到期了，我提前续费同一个套餐，新购买的时间和流量会叠加吗？还是会覆盖原来的？
**A**：不同机场后端的面板策略略有差异：在常见的 **V2Board / Xboard** 面板中，如果是**续费同款周期套餐**，有效期通常会自动向后顺延叠加；但如果你是**从“147 永久流量包”中途购买了“月付/年付周期套餐”**，部分系统会覆盖当前方案类型！因此，在更换不同形态的套餐（尤其是永久包与周期包互换）前，务必先看清结算页面的弹窗提示，或提前发工单向客服确认叠加规则，避免误覆盖造成损失。
